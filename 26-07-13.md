## Work Done

### Added `--leak-check` memory leak detector to MyLang

- `src/main.c`: parse the new `--leak-check` CLI flag and pass it to `codegen_program`.
- `src/codegen.h`: extended `codegen_program` signature with `int leak_check`.
- `src/codegen.c`: when `leak_check` is enabled, emit an extra runtime into the generated C file:
  - `ObjHeader` gains `next`, `prev`, and `alloc_trace` fields.
  - Every allocation via `mylang_new_object` / `mylang_new_array` is inserted into a global circular doubly-linked list.
  - Every release via `mylang_release` removes the block from the list before `free(h)`.
  - On the first allocation, `atexit(mylang_leak_check)` is registered.
  - At exit, `mylang_leak_check` prints any remaining blocks with address, type_id, refcount, length, and the allocation stack trace.
  - Stack traces are stored in a hash table (512 buckets) so identical call stacks share one `LeakTrace` record.
  - A global lock protects the list and the hash table: `SRWLOCK` on Windows (`SRWLOCK_INIT`), `pthread_mutex_t` with `PTHREAD_MUTEX_INITIALIZER` on POSIX.
- `test_runner.py`:
  - Added `--leak-check` argument; when enabled, passes the flag to `mylang.exe`.
  - In `--mode debug` or when `--leak-check` is enabled, captured stdout/stderr is now printed for passing tests so the CRT leak dump or the MyLang leak report is visible.

### Notes

- WeakRef allocations are not tracked; only `ObjHeader` based allocations (class instances and dynamic arrays) are tracked, because user-level leaks are expected to be `ObjHeader` leaks (e.g. circular references).
- The Windows lock uses `SRWLOCK` instead of `CRITICAL_SECTION` because `SRWLOCK_INIT` is a static initializer, avoiding C's restriction on function calls in static initializers.
