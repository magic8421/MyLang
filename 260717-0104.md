# Architecture Review: MyLang front-end + runtime

Scope covered: `lexer.c/h`, `token.c/h`, `parser.c/h`, `ast.c/h`, `symtab.c/h`, `runtime.c/h`, `mangle.c/h`, `util.h`, `main.c`, plus targeted lookups into `codegen.c` for coupling questions only.

## 1. Actual bugs

- [x] **HIGH — stack/heap buffer overflow parsing >8 generic parameters** — `parser.c:1047-1094`. `char params[MAX_GENERIC_PARAMS][64]` (8×64 on stack) is written at `params[param_count]` with no bound check before `param_count++` (`parser.c:1058-1060`). A 9th type parameter overflows the stack buffer; `info->generic_has_new[param_idx]` (`parser.c:1071`) and `generic_constraints[param_idx][...]` (`parser.c:1081`) also index past their `[8]` arrays in the heap `ClassInfo`. The use-site (`parse_base_type`, `parser.c:187-193`) is bounded — the definition site is not.
Direction: add `if (param_count >= MAX_GENERIC_PARAMS) { error; break; }` at loop top.

- [x] **HIGH — `mylang_array_push` releases uninitialized memory for interface/weak element kinds** — `runtime.c:292-326`. `slot = data + length*elem_size` is a brand-new slot (reserve/realloc never zero it, `runtime.c:216-223`), yet the INTERFACE, WEAK_CLASS and WEAK_IFACE cases read the slot first: `mylang_release(((AnyInterface*)slot)->data)` (`runtime.c:304`), `mylang_weak_release(*(WeakRef**)slot)` (`runtime.c:309`), `mylang_weak_release(((AnyWeakInterface*)slot)->wr)` (`runtime.c:314`). That is a release/atomic-dec on a garbage pointer. The CLASS case (`runtime.c:300-302`) does it correctly by overwriting without reading. Pattern looks copied from an element-replacement helper. Tests may pass because fresh heap pages are zeroed; any realloc-reused buffer turns this into a crash or refcount corruption. (Not reproduced — read-only role — but the UB is unambiguous from the code.)
Direction: drop the pre-release in push for these kinds (matching the CLASS case), retain/copy only.
Fixed: push now retains/weak-copies the incoming value without touching the uninitialized slot; also fixed the weak class array element C type name (`WeakRef*`) and weak class/interface element assignment refcounting in codegen (new `mylang_weak_init_owned` runtime helper). Regression tests: `iface_array_push`, `weak_class_array_push`, `weak_iface_array_push`, `weak_class_array_elem_assign`, `weak_class_array_elem_assign_strong`, `weak_class_array_elem_assign_owned`, `weak_iface_array_elem_assign`.

- [x] **MEDIUM — unbalanced `symtab_exit_scope` for integer match arms** — `parser.c:801-805` sets int-arm `ast_resolved_type` to `TYPE_I32`; `parser.c:829` enters a scope only for type-pattern arms; but `parser.c:842-845` calls `symtab_exit_scope()` for every arm whose type is not `TYPE_VOID` — i.e. int arms pop a scope they never entered, consuming the enclosing method/function scope. No visible failure today because the parser never looks up locals and codegen re-tracks scopes independently (`codegen.c:2763-2789`, `3682`, `3771`), but the scope stack is corrupted for the rest of the enclosing function.
Direction: discriminate on `type_kind == TYPE_CLASS` or an explicit flag, not `!= TYPE_VOID`.

**MEDIUM — lexer errors never reach `parser->had_error`** — `lexer.c:357-361` ("unexpected character") returns `TOK_EOF`, so top-level garbage after a complete program silently truncates the compile with exit code 0 (`main.c:91` only checks `parser_had_error`). `lexer.c:178, 203, 217, 226` return dummy string/char tokens with only stderr text. Inside blocks it usually cascades into a parser error, but the error channel is informal.
Direction: add an error counter to `Lexer` and OR it into `had_error` in `parser_init`/`parser_had_error`.

**MEDIUM — `ast_clone` drops node fields** — `ast.c:182-193` copies kind/token/resolved_type/children/next but not `ast_is_native` (`ast.h:104`) or `ast_match_var` (`ast.h:103`). Cloning happens for generic class instantiation (`symtab.c:878`), so a generic class containing a `native` method or a `match` type-pattern arm loses that information in the instantiated copy.
Direction: copy the scalar fields explicitly in `ast_clone`.

## 2. Layering / pipeline

- The nominal pipeline is `lex → parse → codegen` (`main.c:83-116`), but there is **no semantic pass**: type/semantic checks are scattered across all three back-end-adjacent modules:
  - parser: weak-requires-class (`parser.c:215-223`, `428-437`), `new` on interface/struct (`455-463`), struct fields primitive-only (`992-996`), array-by-value returns and non-ref array params (`1202-1216`, `1342-1356`, `1428-1442`), reserved names (`1033`, `1273`), assignment-context restrictions (`29-55`, `643-651`, `868-872` …).
  - symtab: interface implementation validation (`symtab.c:399-513`), generic constraint validation (`symtab.c:583-651`, `777-813`), generic method-call validation (`symtab.c:699-775`).
  - codegen: all expression type resolution plus it *triggers* validation (`codegen.c:3828` calls `symtab_validate_impls`).
- Validation orchestration is split oddly: `symtab_init` is called from `parser_parse_program` (`parser.c:1507`), `symtab_validate_generic_method_calls` from `parse_class_decl` (`parser.c:1255`), `symtab_validate_impls` from codegen. main.c orchestrates only two of the four real stages.
- **Parser and codegen each run a full scope lifecycle over the same global symtab**: parser enters/exits scopes and inserts every local (`parser.c:1155/1226`, `1394/1445`, `723`, `829/844`); codegen re-enters scopes and re-inserts the same symbols (`codegen.c:2364`, `2763-2789`, `3482-3518`, `3682-3707`, `3771-3808`). Two parallel scope disciplines is the main entanglement; the match-arm bug above is harmless only because of this redundancy.
- **Symtab is a god module** (medium): it combines builtin registration (`symtab.c:23-136`), scope hash table, five registries, interface validation, a mini expression type-resolver (`symtab.c:653-697`), and the entire generic-instantiation engine including AST cloning/substitution (`symtab.c:777-889`). Direction: split storage/scopes from `sema` (validation) and `instantiate` (generics).

## 3. Error handling

- Parser: consistent `fprintf(stderr, "error at %d:%d: ...")` + sticky `had_error`, limited recovery (`parser.c:20-27`, `954-958`). Good.
- Symtab validation errors have **no line info** (`symtab.c:408, 419, 440, 460, 473, 502, 543, 784, 801, 808`) — inconsistent with parser diagnostics. `InterfaceMethodInfo.interface_method_line` exists (`symtab.h:30`) but is unused for this.
- `CHECK_STRSCPY`/`CHECK_SNPRINTF` abort with `exit(1)` and no source location (`util.h:23-37`) — acceptable per documented policy, but note the mixed model: flag-and-continue (parser) vs error-count-return (symtab) vs abort (util) vs silent-stderr (lexer).
- Several overflow paths print or fail without setting any error flag: `symtab_add_class_impl` over MAX_IMPL prints but parse continues and can exit 0 (`symtab.c:356-361`, called `parser.c:1117`); `symtab_add_field`/`symtab_add_struct_field` return -1 which both call sites ignore (`parser.c:1240`, `1009`); `symtab_add_interface_method` silently drops methods past 32 (`symtab.c:331`); `ast_add_child` prints but doesn't propagate (`ast.c:15-21`).

## 4. AST design

- Uniform construction via `ast_new_node` + `calloc` (`ast.c:8-13`) — fine. Fixed 4-child array + `next` list is simple and works; `ast_add_child` overflow only prints (above).
- Nodes are heavy (~600 B: full `Token` with `text[256]`, full `Type` by value with `mangled_name[128]`, plus `ast_temp_name[64]`, `ast_match_var[64]`) — acceptable for one-shot, but `ast_temp_name`/`ast_match_var` are codegen concerns crammed into the generic node; `ast_match_var` exists solely for match arms.
- `Type` embeds heap `type_args` yet is routinely copied by value (`parser.c:722`, `symtab.c:161`…); shared `type_args` pointers are safe only because AST types are never freed. The `type_new`/`type_free` discipline in generics (`ast.c:107-139`, `symtab.c:557-576`) proves partial ownership exists anyway — document that "no deallocation" applies to AST nodes, not to `Type` internals.
- No arena; per-node calloc. No risk beyond memory for a one-shot compiler.

## 5. Runtime

- API surface is coherent: consistent `mylang_*` prefix, array helpers share `(a, …, elem_size, elem_kind)` ordering. Nits: `mylang_lock` breaks the `mylang_weak_*` family naming (`runtime.h:149`); `mylang_release` returns `int` that is always 0 (`runtime.c:55-64`) — dead return value.
- Atomic portability is handled but stylistically mixed on POSIX: `atomic_fetch_add/sub` for inc/dec vs `__sync_val_compare_and_swap` for CAS (`runtime.h:18-20`); passing `volatile long*` to `atomic_fetch_*` is technically not conformant (`_Atomic` required) though it works on GCC/Clang via `__atomic` builtins.
- `mylang_lock` has a theoretical UAF race (`wr->obj` read non-atomically, then dereferenced after possible free — `runtime.c:373-384`) — irrelevant until the language has threads.
- Unchecked `calloc` in `mylang_new_object` (`runtime.c:39`) and `mylang_weak_init` (`runtime.c:361`); `realloc` IS checked in reserve/compact — inconsistent.
- Leak-check list/hash implementation (`runtime.c:395-547`) looks correct: circular doubly-linked list, locked, atexit registered once.

## 6. Cross-module coupling

- No circular header includes. `main.c` is clean and minimal.
- `symtab.c` exports `class_list` and `interface_list` as non-static globals **not declared in `symtab.h`** (`symtab.c:9, 11`); codegen grabs them via local `extern` declarations (`codegen.c:67`, `261`, `352`, `3371`, `3403`, `3455`) — while structs/funcs get proper accessors (`symtab_first_struct`, `symtab_first_func`). Inconsistent API surface.
- `runtime.c:2` includes `ast.h` and uses nothing from it (verified by grep) — the target runtime should not include the compiler front-end header.

## 7. Convention compliance

- **Naming-prefix convention is only partially honored.** Compliant: `AstNode` (`ast_*`), `Type` partially (`type_kind`, `class_name`, `type_id` but unprefixed `is_pointer`, `is_array`, `array_size`, `is_ref`, `is_weak` — `ast.h:46-50`), two fields of `InterfaceMethodInfo`. Non-compliant: `Token` (`token.h:77-85`), `Lexer`, `Parser`, all `symtab.h` structs (`MethodInfo.name`, `ClassInfo.name`, `Scope.table/level`…), all `runtime.h` structs. Either enforce or soften AGENTS.md.
- "All snprintf and strscpy call sites are checked" — **false globally**. True for `ast.c`, `mangle.c`, `parser.c`, `symtab.c`. `runtime.c:122-155` uses `if (n > 0)` guards into worst-case-sized buffers (safe, but not CHECK_SNPRINTF); `main.c:39-51` checks manually but *clamps* instead of aborting (different failure semantics); `codegen.c` has many unchecked `snprintf` calls (e.g. `codegen.c:117-156`, `1047-1049`, `3083`) — left for the codegen agent to detail.
- Comments are plain English, ASCII-only (grep-verified), no emoji ✓.
- Redundant `info->name[63] = '\0'` after CHECK_STRSCPY (`parser.c:979`, `1041`, `1291`) — dead lines; `strscpy` guarantees termination.

## 8. Smaller findings (low)

- `parse_relational` (`parser.c:605`) is dead code with a stale `??handle inline below` comment (`parser.c:606`); superseded by `parse_relational_full` (`parser.c:608`).
- `AST_OUT_ARG` (`ast.h:91`) is a leftover from the removed `out` keyword.
- `Scope.level` written, never read (`symtab.c:27, 141`); `symtab_current_scope` never called.
- `is_native` parsed but unused in struct bodies — `native` is silently accepted on struct fields (`parser.c:986-990`).
- Direct assignment as a variable initializer (`i32 x = y = 5;`) is accepted — `parser.c:712` explicitly exempts `expr_is_direct_assignment(init)` — contradicting AGENTS.md ("not allowed in variable initializers"). Doc/impl mismatch one way or the other.
- Integer literals go through `atoi` into a 32-bit `int int_val` (`lexer.c:160`, `token.h:82`) and are emitted as `%d` (`codegen.c:1109`, `2879`) — i64/u64 literals overflow silently; no hex/exponent support; `Token.float_val` is written but never read anywhere.
- Duplicate definitions unchecked: duplicate class names (interface decl checks conflicts at `parser.c:1280-1285`; class/struct decls don't), duplicate fields (`symtab_add_field` no dup check), duplicate locals/params in one scope (`symtab_insert` no `lookup_current` check). These surface later as C compile errors or wrong-symbol resolution.
- f-string sub-parser errors report line 1 of the snippet — the `line`/`col` parameters are accepted and discarded (`parser.c:253-254`); trailing garbage in `{…}` is ignored (no EOF check after `parse_expr`).
- `main.c:19` `fread` return unchecked; a codegen failure leaves a partially written `.c` file behind.
- Type-pattern match arm stores the pattern class name in `ast_match_var` via the arm token, fine — but `arm->ast_match_var` duplicates `ast_resolved_type.class_name` (`parser.c:826`).

## What is fine (do not re-check)

- Lexer EOF safety: `read_char_literal` guards verified (`lexer.c:216, 225, 243`); `lexer_peek_ahead` only ever reads offset 1 and the buffer is NUL-terminated (`main.c:20`), so no over-read.
- Token text truncation at 255 is safe (`lexer.c:107-109`); `class_name[64]` boundaries are all CHECK-guarded.
- `type_equal` is thorough, including recursive type-arg comparison (`ast.c:54-72`).
- Interface validation in `symtab_validate_impls` is genuinely complete: unknown interface, duplicate impl, cross-interface signature conflicts, missing-method vs default body, `override` verification (`symtab.c:399-513`).
- Builtin `String` registration in symtab matches the runtime layout exactly (`symtab.c:34-106` vs `runtime.h:67-69`).
- Parser assignment/inc-dec context restrictions (conditions, call args, f-strings, match expr) are systematically applied via `expr_contains_assign`/`expr_contains_inc_dec`.
- Array core logic (reserve growth, resize release/zero, move, copy-with-retain for all five elem kinds, bounds check) is correct; the push bug above is the sole exception.
- Pipeline in `main.c`, header include graph, mangle recursion with CHECK guards, hash/scope mechanics — all sound.
