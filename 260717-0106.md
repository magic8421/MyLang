# Codegen Architecture Review: `src/codegen.c` / `src/codegen.h`

## 1. Actual bugs / fragile spots (highest priority)

[x] **[HIGH] Loop conditions containing class/interface-returning calls are compiled to evaluate once, before the loop — stale condition, miscompile.**
`codegen_while_stmt` calls `prepare_expression(ctx, cond, ...)` at `src/codegen.c:2602`, *before* emitting `while (1)` at 2615. `emit_guarded_temp_decls_impl` (1629–1697) hoists any guarded call (e.g. `w.lock()`, `list.get(i).shape()`, any method returning a class) into a `_gN` temp declared and assigned once before the loop; thereafter `codegen_expr` short-circuits on `ast_temp_name` (1102–1105), so the loop tests the first iteration's value forever. `while (w.lock())` on a live object is an infinite loop; `while (foo() != expected)` never re-calls `foo()`. Same for `for` conditions (2672–2678). The parser only bans assignment/inc-dec in conditions (`src/parser.c:749,869,892`), so this is reachable, and no test exercises a method call in a `while` condition (grep over `test/` found none). Bonus damage: the `_gN` ref is cleanup-tracked in the function scope *before* the loop-entry snapshot (2608), so it is held until function exit.
*Direction: re-emit the guarded temp assignments at the top of each loop iteration (or extract the condition into a per-iteration re-evaluation block), not before `while(1)`.*

**[MEDIUM] Assignment with a call as the member-access receiver is double-evaluated and leaks.**
For `make().field = x`: `emit_guarded_temp_decls_impl` skips ASSIGN LHS entirely (1643–1647), and `emit_subexpr_temps_impl` also skips LHS (1805–1810, "LHS must remain an lvalue"). Then the class-assignment branch in `codegen_expr` emits `codegen_expr(ctx, lhs)` twice — release and store (1356–1361) — so the receiver call runs twice: double side effects and the first +1 reference leaks. No test covers this pattern.
*Direction: hoist a non-trivial member-access receiver into an `_iN` temp before assignment codegen (extend `subexpr_needs_temp` handling to ASSIGN LHS receivers).*

**[MEDIUM] Fixed-size-array over-read on deeply nested loops; silent cleanup-cap drops.**
`loop_entry_cleanup_count[64]` etc. are *written* under a `loop_depth < MAX_LOOP` guard (2607, 2665) but *read* unguarded in `codegen_break_stmt`/`codegen_continue_stmt` (2736–2738, 2751–2753): at nesting depth ≥ 65 `idx` ≥ 64 → out-of-bounds stack read feeding a cleanup count. `cleanup_add*` silently drops entries once `cleanup_count == MAX_CLEANUP` (128) (e.g. 2106) — a long straight-line function with >128 guarded temporaries in one scope leaks without any diagnostic. `cleanup_push_scope` past depth 64 is also silently ignored (2230), corrupting pop pairing.
*Direction: emit a compile error (set `codegen_error`) on any of these overflows instead of continuing.*

**[MEDIUM] Unchecked `snprintf` sites despite AGENTS.md claiming "all call sites are checked".**
Violations: `c_weak_interface_name` (117), `c_array_elem_type_name` (134–139), `array_elem_size_expr` (146–156), `codegen_new` dtor name (1047, 1049), `emit_compound_lvalue_temp` into `ast_temp_name` (3083). The 1047 case is genuinely truncatable: `dtor_name[128]` = `"_mylang_dtor_"` (13 chars) + `mangled_name[128]` → truncated destructor name → undefined symbol at C link time for long generic instantiations. Other sites produce silently wrong C.
*Direction: route through `CHECK_SNPRINTF` like the rest of the file.*

**[LOW] Fixed temp names `_r` / `_mylang_ret` collide on two returns in one C block.**
`codegen_return_stmt` declares `void* _r` (2972, 2994) and `_mylang_ret` (3038) with no counter. Two `return` statements in the same block (dead code after the first — not rejected) produce a C redefinition error (C2374) instead of a MyLang diagnostic.
*Direction: use `assign_tmp_id` like `_iret%d` does.*

## 2. Error handling consistency

**[MEDIUM] Several error paths print to stderr but never set `ctx->codegen_error`, so `main.c:120` reports success.**
Missing flag at: array arg passed by value (654–658), ref arg not an identifier (669–673), ref arg unknown variable (675–680), weak-interface arg type mismatch (721–723). Worse, the catch-all defaults emit output comments with *no* error at all: `codegen_expr` default → `/* ??? */` (1517–1519), `codegen_stmt` default → `/* unknown stmt kind */` (3360–3363). Result: broken generated C that either fails `cl` with a cryptic message or, worse, compiles. The 39 `codegen_error = 1` sites are otherwise consistent (`fprintf stderr` with `line:col`, flag set, placeholder emitted).
*Direction: set the flag at every error print; make the two `default:` cases hard errors.*

## 3. Internal structure / god functions

**[MEDIUM] The file has reasonable sectioning but three god functions.**
Sections are roughly: type-name helpers → header emission → `resolve_type` → expression codegen → guard/temp machinery → cleanup list → statement codegen → interface/vtable emission → program driver. The monsters:
- `codegen_expr` — 423 lines (1098–1521); the AST_ASSIGN arm alone is ~300 lines of interleaved weak/interface/class refcount logic.
- `codegen_expr_stmt` — 238 lines (3086–3324); re-implements assignment semantics for IDENT LHS.
- `codegen_var_decl` — 227 lines (2354–2581); re-implements the same conversions a third time for initializers.
`resolve_type` (441–616, 176 lines) and `codegen_match_stmt` (2795–2955) are borderline. Also note the assignment logic is doing several jobs at once: lvalue emission, refcount protocol, *and* type validation (primitive checks at 1148–1159, 1186–1197, 3111–3123).

## 4. Duplication

**[HIGH] The weak-interface / interface / class assign-and-convert protocol is implemented 5 times.**
Same `wr`/`vt`/`mylang_weak_init`/`mylang_release` decision tree appears at: `codegen_expr` ASSIGN (1310–1467), `codegen_expr_stmt` IDENT LHS (3142–3297), `codegen_var_decl` init (2382–2551), array-element assignment (1210–1306), and `codegen_call_arg` weak-interface conversion (692–737). These already diverge stylistically (comma-expressions vs `_wassignN` temps vs statement sequences), so a semantic fix must be replicated five ways — exactly how the bug in §1.2 survives.
*Direction: one `emit_weak_iface_assign(ctx, lhs_emit_fn, rhs, owned)` helper; the class/interface cases similarly.*

**[MEDIUM] `cleanup_emit` / `cleanup_pop_scope` / `cleanup_emit_to` are three near-identical 33-line dispatch bodies** (2194–2306) differing only in loop bounds and whether `cleanup_count` is reset; the five `cleanup_add_*` functions (2105–2192) repeat the same 10-field initialization. One parametrized `cleanup_emit_range(ctx, from, to, indent)` and a kind enum would delete ~150 lines.
**[LOW]** C parameter-list printing is re-implemented 6 times (375–390, 406–437, 3379–3395, 3468–3476, 3551–3559, 3668–3680, 3744–3763); the weakify/lock helper emission (3402–3452) is five copy-pasted fprintf blocks.

## 5. Layering

**[MEDIUM] Codegen *is* the semantic phase — this is a deliberate one-shot design but the leakage is real.**
- `resolve_type` (441–616) is full type inference living in codegen: it mutates `node->ast_resolved_type`, does symtab lookups, and even *instantiates generics* (`symtab_instantiate_class_from_type` at 524, 567). It's re-invoked on the same nodes from many sites (`codegen_call` 873, `codegen_member_access` 1009, `codegen_array_access` 996…), making deep expressions O(n²), and it silently yields a zeroed `Type` on unknown input, masking errors downstream.
- Type *validation* sits in codegen: inc/dec and compound-assign primitive checks (1148, 1186, 3111 — the last two are the same check twice), match-arm type compatibility (2864–2937), array-return bans (3652, 3722), ref-arg rules (653–741). `symtab_validate_impls()` is invoked from `codegen_program` (3828) rather than the driver.
- Codegen manages symtab scopes directly: `symtab_insert` for locals (2364), params (3689, 3780), match bindings (2776), and `symtab_enter/exit_scope` (2763, 3482, 3682, 3771). Fragile: codegen and parser must agree on scope structure implicitly.
- Fragile global reach: `extern ClassInfo* class_list` at file scope (67) and `extern InterfaceInfo* interface_list` re-declared inside five functions (261, 352, 3371, 3403, 3455) instead of exported from `symtab.h`.
*Direction: acceptable for a one-shot compiler, but at minimum hoist `resolve_type` into a resolve pass that runs once per node, and move the extern decls to `symtab.h`.*

## 6. State management

**Mostly fine — verified safe, don't re-check:** `CodegenContext` (35–59) is ~15KB on the stack (fine); temp counters (`guard_tmp_id`, `subexpr_tmp_id`, `fstring_tmp_id`, `assign_tmp_id`) are never reset and use distinct prefixes (`_gN`, `_iN`, `_fsN`, `_fse/_fso/_fssN`, `_wassignN`, `_mN`, …), so they **are** collision-safe across nested scopes. Only file-scope mutable is `s_last_codegen_error` (61). Cleanup name pointers are safe because AST nodes and token text live for the whole compilation.

**[LOW]** `fstring_temp_name` (1857–1862) mallocs 64 bytes per temp and never frees — benign in a one-shot compiler, but it's why `cleanup_add` can store the pointer; document or use a small arena.

## 7. Extensibility risks

**[MEDIUM] Adding one AST node kind means updating ~7 hand-written tree traversals.**
`resolve_type` (445), `codegen_expr` (1107), `emit_guarded_temp_decls_impl` (1650), `emit_subexpr_temps_impl` (1739), `emit_fstring_preambles` (2047), `emit_call_guards` (2085), `preinstantiate_generic_types` (188, hard-codes `i < 4`). Miss one and you get a double-evaluation or a leak — the traversals also rely on mutation hacks: temporarily NULLing `a->next` (1657–1662) and detaching f-string parts (1918–1924), plus the parallel callee-resolution logic duplicated between `codegen_call` (895–942) and `call_arg_consumed_by_weak_iface` (1590–1613), which must be kept in sync by hand.
*Direction: a single generic `ast_walk_children` used by all traversals; one shared callee-signature resolver.*

## 8. Dead / confusing code

**[LOW]** `emit_bounds_checks` is a pure no-op recursion (1527–1541) still called from 6 sites (2586, 2603, 2675, 2802, 2962, 3087) — delete it and the call sites. The second `cleanup_pop_scope` in every function/method/default-method emitter (3514+3517, 3703+3706, 3804+3807) is always a no-op (scope depth is already 0 at top level; the early return at 2236 swallows it) — either a missing second push or leftover; confusing either way. `codegen_struct_decl` (3595) is an unused no-op. `emit_interface_c_helpers` emits `static` helpers for every interface even when never called → unused-function warnings in generated C. Builtin call dispatch special-cases only `print` (950–964); any future builtin silently falls through to emitting its bare name as C.

## Convention compliance (verified)

- `ctx->out` convention: held everywhere **except** `emit_function_signature(FILE* out, ...)` (375). Low.
- `MY_LOC`/`__my_line`: matches the documented design — per-statement/per-condition `MY_LOC` with last-line dedupe (2327–2334). Fine.
- Comments: plain English, ASCII-only — verified byte-level over both files. Fine.
- Struct-member prefix convention: **violated** by the two file-local structs — `CleanupEntry` (`name`, `is_weak`, …, 19–31) and `CodegenContext` (`out`, `return_type`, …, 35–59). Low (private structs, but the AGENTS.md rule as written doesn't exempt them).
- `CHECK_SNPRINTF`/`CHECK_STRSCPY`: used correctly at the dangerous sites (temp names, `c_type_str`); the unchecked stragglers are listed in §1.

`codegen.h` itself is minimal and clean — nothing to flag.
